# PCF 安全更新程序

用途：更新 `C:\Users\30855\Desktop\模拟盘2\data\baidu_valuation_latest.csv`，供现有 formal 回测脚本读取。

仓库目录：`日常数据更新/pcf_updater/`。下方绝对路径是当前电脑上的部署示例；下载仓库后先进入实际的程序目录。默认仍使用原电脑上的回测脚本、预测清单和预测文件，这些数据依赖未随本目录上传。更换位置可使用 `--backtest`、`--target` 参数；原回测脚本内引用的预测文件路径也需要有效。

## 已实现

- 默认读取原回测的 `purged` 路径清单，按原逻辑处理目录迁移、分期预测、启用的模型门控和新旧预测接力。也可选 `--pred-source original`。
- 只抽取原回测的指定常量和函数，不导入整个回测模块，不启动 Qlib、不训练模型。
- 下载范围是所选回测区间接力预测中所有股票的并集；默认覆盖脚本所有默认区间。每日前100名用于覆盖率验收，不用当前持仓代替历史股票范围。
- 百度市现率接口，默认“全部”历史；支持超时、重试、4线程。2026-10-19 已真实验证两只股票，可返回1999/2003年至当天的数据。接口返回日期通常不是逐交易日连续，验证沿用原回测的前向填充和滞后一日处理。
- 不沿用旧程序的缓存跳过逻辑，每次请求所需股票。失败保留旧值，负PCF保留，只更新有效PCF，其他字段和历史键保留。
- 默认只写本文件夹下的 `runs\run_时间戳`，生成候选文件和报告，不修改正式数据。
- 发布必须通过全部数据验收，且原始/候选文件哈希未改变；先在目标旁备份，再用临时文件原子替换。没有跳过验收的开关。

依赖 `pandas`、`numpy`、`requests`，本机已验证可用。直接使用 requests 是为每次请求设置明确超时；请求参数与本机 AKShare 的百度估值实现一致。默认使用系统代理环境；网络错误会记录到下载日志，不清除系统代理设置。

## 使用顺序（PowerShell）

先进入程序目录：

```powershell
cd 'C:\Users\30855\Desktop\temporary\pcf_updater'
```

1. 检查所有默认预测文件和原数据，不联网下载：

```powershell
.\Update-PCF.cmd --plan
```

也可双击 `Check-PCF.cmd`。输出文件夹包含股票清单、每个预测文件实际路径和哈希、前100名所需日期、更新前覆盖情况。

2. 小范围联网测试（不能发布）：

```powershell
.\Update-PCF.cmd --cases 2026YTD --limit 2
```

3. 全量下载并生成候选数据（仍不修改正式文件）：

```powershell
.\Update-PCF.cmd
```

也可双击 `Download-PCF.cmd`。所有默认区间可能涉及数千只股票，耗时取决于网络。只更新某个区间可用 `--cases 2026YTD` 或 `--cases 2025H2 2026YTD`；验收仅对选定区间负责，其他历史仍保留。每次均生成独立运行目录，下载中断后可重跑；目前不支持断点续传。

4. 打开本次 `验证报告.md` / `report.json`。仅当 `accepted` 为 `true` 时发布：

```powershell
.\Update-PCF.cmd --publish-run 'C:\Users\30855\Desktop\temporary\pcf_updater\runs\run_实际时间戳'
```

发布时停止其他可能写入该 CSV 的程序，并在发布后重启使用该 CSV 的回测工作进程，使其重新载入数据。该命令会对桌面“模拟盘2”目录写入数据；在受限环境中需要该目录的写权限。

回滚：停止读写该文件的程序，把 `published.json` 中的 `backup` 文件复制回 `target`。建议先把待回滚的当前文件另存，再执行恢复。

## 数据验收门槛

以下任一项失败，禁止发布；不会自动降低标准：

1. 不是 `--limit` / `--symbols` 的测试运行，全部请求成功且有有效数据。
2. 文件格式、日期、股票代码、有限数值、股票日期唯一键有效。
3. 原历史键全部保留；原非空PCF不被空值擦除；其他估值列值不变。
4. 用原函数 `stabilize_signal`、`attach_valuation(lag_trading_days=1)`、`apply_pcf_q90` 检查：评估期每日前100名PCF全覆盖，且覆盖率不下降。接力预热期参与对齐，但不混入评估期覆盖统计。
5. 各所需股票的最新有效源日期至少覆盖该股票最后一个入选前100名日期所需的上一信号日。最新日期仅作额外检查，不代表每条历史记录都是当时已发布的数据。
6. 验证期间原CSV、预测来源未变化。发布时原CSV及候选文件哈希未变化，备份校验通过。

旧数据本身有缺口、退市股票、接口无记录等情况可能导致验收不通过。这时查看缺口列表，补充可信数据来源后重新验证；程序不会用0或其他股票数值补齐。数据验收不证明历史估值未被供应商事后修订，也不证明网络数据对应当日盘前已知信息。

完整 Qlib 回测未纳入自动运行；程序已经调用原回测的基础 q90 过滤函数验证数据接入。策略收益和所有风险变体应在正式使用候选数据时另行回测，收益提高不作为数据验收标准。

## 输出文件

| 文件 | 内容 |
|---|---|
| `original.csv` | 原文件字节备份（每次运行的快照） |
| `prediction_sources.json` | 实际使用的前期/当期预测、哈希、区间 |
| `instruments.csv` | 所选接力预测的全部股票 |
| `requirements_top100.csv` | 评估期前100名及其上一信号日 |
| `download_log.csv` | 每只请求的状态、返回日期范围、错误 |
| `downloaded.csv` | 本次接口原始整理结果 |
| `candidate.csv` | 新旧合并后的候选文件 |
| `pcf_changes.csv` | 发生变化的PCF单元格及前后值 |
| `coverage_before.csv` | 原数据前100名覆盖和基础筛选 |
| `coverage_comparison.csv` | 覆盖、正PCF和筛选前后变化 |
| `coverage_daily.csv` | 按回测区间、日期汇总 |
| `missing_top100.csv` | 前向填充并滞后后仍缺失的记录 |
| `freshness.csv` | 每只所需股票的日期覆盖检查 |
| `stock_date_ranges.csv` | 候选数据中各股票有效PCF日期范围 |
| `验证报告.md` / `report.json` | 验收结果与统计 |
| `published.json` | 成功发布后记录目标和正式备份路径 |

退出码：`0` 为检查完成/数据验收通过/发布成功；`2` 为已生成候选但未通过验收；`1` 为运行错误。退出码2不代表数据被删除，也不表示已发布。
